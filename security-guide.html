1. Overview

Espresso Tracker implements a comprehensive security architecture using JWT (JSON Web Token) authentication, Spring Security, and role-based authorization. This document details all security measures implemented across the backend API and React frontend.

2. Authentication

2.1 JWT Token-Based Authentication

The application uses HMAC-SHA384 signed JWT tokens for stateless authentication.

PropertyValue
AlgorithmHMAC-SHA384 (HS384)
Token Lifetime24 hours (86,400,000 ms)
Secret Storageapplication.properties (Base64-encoded)
Token Structure{ sub: username, role: "USER"|"ADMIN", iat: timestamp, exp: timestamp }

2.2 Login Endpoint

POST /api/v1/auth/login
Content-Type: application/json

Request:  { "username": "admin", "password": "admin123" }
Response: { "token": "eyJ...", "username": "admin", "role": "ADMIN" }

2.3 Registration Endpoint

POST /api/v1/auth/register
Content-Type: application/json

Request:  { "username": "newuser", "email": "user@example.com", "password": "password123" }
Response: { "message": "User registered successfully" }
  • Passwords are hashed using BCrypt before storage
  • Username must be 3-50 characters
  • Email is validated for format
  • Password must be at least 6 characters
  • Duplicate usernames and emails are rejected with HTTP 400
  • New users are always created with USER role

4. Security Components

4.1 SecurityConfig.java

  • @EnableMethodSecurity — Enables @PreAuthorize annotations on controller methods
  • CSRF disabled — Stateless JWT doesn't require CSRF protection
  • Stateless sessions — No HTTP sessions created
  • Password encoding — BCryptPasswordEncoder for all passwords
  • AuthenticationManager — Configured for username/password authentication

4.2 JwtService.java

  • Token generation with HMAC-SHA384 signing
  • Token validation (signature verification + expiration check)
  • Username extraction from token subject claim
  • Custom claims support (role embedded in token)

4.3 JwtAuthenticationFilter.java

  • Runs once per request (extends OncePerRequestFilter)
  • Extracts Authorization: Bearer header
  • Validates token signature and expiration
  • Sets SecurityContext with user authorities
  • Allows unauthenticated requests to pass through filter chain

4.4 CustomUserDetailsService.java

  • Loads users from database by username
  • Returns UserDetails with BCrypt password and ROLE_USER or ROLE_ADMIN authority
  • Transactional read-only for database efficiency

4.5 @PreAuthorize Annotations

Method-level security annotations on controllers:

@PreAuthorize("hasRole('ADMIN')")
public ResponseEntity createBean(...)

@PreAuthorize("hasRole('ADMIN')")
public ResponseEntity updateBean(...)

@PreAuthorize("hasRole('ADMIN')")
public ResponseEntity deleteBean(...)

@PreAuthorize("hasRole('ADMIN')")
public ResponseEntity logBrew(...)

6. Frontend Security

6.1 JWT Token Management

  • Token stored in localStorage for persistence across page reloads
  • Axios interceptor automatically attaches Authorization: Bearer header to all requests
  • Logout clears token from localStorage

6.2 Protected Routes

  • React Router routes wrapped with component
  • Unauthenticated users are redirected to /login
  • Loading state shown while auth state initializes from localStorage

8. Security Recommendations

  1. Change the default admin password immediately in production
  2. Replace the JWT secret (jwt.secret in application.properties) with a strong, unique Base64-encoded key
  3. Use HTTPS in production to encrypt token transmission
  4. Set shorter token expiration (jwt.expiration-ms) for higher security environments
  5. Implement token refresh for better user experience
  6. Add rate limiting to login and registration endpoints
  7. Use environment variables for secrets instead of application.properties
  8. Add audit logging for admin actions (create/update/delete operations)
  9. Implement account lockout after multiple failed login attempts
